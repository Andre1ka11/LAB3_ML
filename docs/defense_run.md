# Единый комплект для защиты

Открыть **notebooks/defense.ipynb**. Все 33 вычислительные ячейки уже выполнены; таблицы, исходные примеры и 11 графиковых файлов сохранены. Перед каждым логическим вычислительным блоком объясняется цель, после результатов — их смысл и границы вывода. Каждый график вынесен отдельно и сопровождается объяснением осей, обозначений и наблюдаемых результатов. Начало содержит словарь для читателя без подготовки в ML. Блокнот содержит маршрут пятиминутного выступления и подробные дополнительные проверки.

Для чтения и подготовки: **docs/defense_guide.pdf** (версия для печати), **docs/defense_guide.html** (автономный HTML с оглавлением и встроенными изображениями), **docs/defense_guide.md** (текст в GitHub). Это личное учебное пособие объёмом около 8 тысяч слов: объяснения результатов, формулы, восемь разборов ошибок, все 12 вопросов методички, дополнительные вопросы, ограничения и сценарий защиты. Самостоятельные выводы команды и две независимые оценки не подменяются.

## Перезапуск анализа

Python 3.11 или совместимая версия; GPU, llama-cpp-python, веса и ключи не нужны.

```powershell
python -m venv .venv-defense
.venv-defense/Scripts/python.exe -m pip install -r requirements-defense.txt
.venv-defense/Scripts/python.exe scripts/execute_defense_notebook.py
```

Либо выбрать это окружение в PyCharm/Jupyter и выполнить Run All. Во время анализа HTTP-транспорты блокируются; новые ответы моделей и исполнения их программ не запускаются. Заново обучаются только доверенные LR/NB на сохранённых train5/train20. После Run All можно открыть готовые выводы без ядра и сети.

Обновление текстового пособия по пересчитанным таблицам:

```powershell
.venv-defense/Scripts/python.exe scripts/build_defense_guide.py
```

PDF уже приложен. Его необязательная повторная генерация на Windows требует установленного Edge и пакета playwright (`pip install playwright`, затем `python scripts/render_defense_guide.py`); для самого блокнота playwright не нужен.

## Проверки происхождения

Замороженные источники в analysis/defense/source_manifest.json созданы на основе main commit `1d1ce750aa7e8dcc33d7edb135852affef6369d6`. Блокнот проверяет hashes, 1376 уникальных ответов, все started-payloads, параметры, разделение данных, Git-объекты регистраций до первого started основного банка, DeepSeek snapshot, разрешённые сетевые повторы и воспроизведение baseline по каждому row_id.

Hash-проверка подтверждает согласованность и неизменность относительно снимка, но не является цифровой подписью провайдера. Для внешнего подтверждения используются кабинеты/Billing. В конце есть отдельная live-ячейка, по умолчанию LIVE=False: она может потреблять токены и никогда не добавляется в первоначальные оценки.

**Не запускать --freeze-sources для обхода упавшего assert.** Эта опция builder предназначена для явной подготовки нового проверенного снимка, а не для автоматического принятия любых изменений. Обычный Run All её не вызывает. Если исходный файл действительно обновился, сначала проверить причину и зафиксировать новую версию данных отдельным изменением.

Новые live-probe файлы игнорируются Git и не входят в замороженный эксперимент. Ключи не пишутся в ноутбук или отчёт.

## Что измерено и что ещё не измерено

A/B/F: 24 автоматические оценки на модель. E: 100 строк на каждый shots. Проверка по содержательным рубрикам задания выполнена: все 92 ответа B/C/D, оценки 0–2, шесть флагов D и обоснования сохранены в data/reviews/defense_expert_review.json и docs/expert_review.md. В блокноте показаны сводка и все построчные решения; C/D включены в тепловую карту. Это одна экспертная проверка; две независимые слепые оценки участников ещё не зафиксированы, kappa не заявляется. Дополнительный составной результат 39 задач подписан отдельно и не заменяет зарегистрированные A/B/F. Giga первичный JSON-неуспех D и post-hoc диагностика извлечённого кода разделены. У DeepSeek incomplete не смешивается с содержательным отказом.

Скрипты пересчёта пишут только analysis/defense; исходные модельные журналы и индивидуальные отчёты сохраняются. Семейство exact McNemar теперь включает все шесть пар четырёх моделей с Holm. Основная H5 остаётся зарегистрированной парой Yandex–Qwen.
