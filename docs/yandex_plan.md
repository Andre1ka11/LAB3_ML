6. Resume пропускает уже завершённые запросы. Неверный ответ, отказ, обрезанный ответ или невалидный JSON тоже считаются полученными результатами; не перезапрашивать их ради улучшения качества.

## 5. Параметры и ограничения

- Явная модель: gpt://<folder_id>/yandexgpt-5.1; без плавающего latest.
- Один новый диалог на задачу; temperature=0, без веб-поиска и инструментов. Точные параметры и фактически поддерживаемый режим фиксировать в логе.
- Один последовательный поток на первом прогоне. Ускорение не является приоритетом до устойчивого пилота.
- Общий достаточный лимит выхода: предложение 4096 токенов для всех запросов, согласовать с командой. Лимит - потолок, он не означает оплату 4096 токенов за каждый ответ. Промпт требует краткое обоснование; больший лимит нужен прежде всего коду.
- Ответ сохранять даже при ошибке парсинга. Нельзя обрезать ответ вручную или молча подменять режим после старта.
- На явный 429: учесть Retry-After и ограниченное число повторов, каждый записать. На 401/403 остановиться и исправить доступ. На неоднозначный timeout/обрыв остановиться: сервер мог уже обработать и тарифицировать запрос. Не включать бесконтрольные автоматические повторы POST.

## 6. Бюджет и точки остановки

Тариф проверен 19 ноября 2026: для синхронного YandexGPT Pro 5.1 вход и выход по 0.80 рубля за 1000 токенов. Источник: https://aistudio.yandex.ru/ru/docs/ai-studio/pricing . Без инструментов расчётная стоимость = 0.0008 * (input_tokens + output_tokens).

В фактических 344 русских запросах 802815 символов вместе с повторением system prompt. Грубая эвристика 2-4 символа на токен даёт 200704-401408 входных токенов, то есть примерно 161-321 рубль только за вход. Это не точная токенизация и не верхняя граница. Если выход составит ещё 100000-200000 токенов, общий расход будет примерно 241-481 рубль. Рабочий ориентир с запасом: 250-600 рублей, уточнить после пилота; это не обещание стоимости.

Предлагаемые локальные стоп-пороги для нашей Yandex-части:

- Пилот: до 10 рублей; при превышении остановиться и проверить причину.
- Весь прогон: расчётный лимит 1000 рублей, включая пилот и повторы; не расходовать все 4000.
- Перед стартом каждого блока оценить остаток плановых запросов и заложить резерв. При риске превышения лимита не начинать следующий блок, а пересчитать план.
- Для предварительной точной оценки входа можно использовать официальный бесплатный токенизатор после проверки условий его API; сейчас он не вызывался. Учет usage сохранять всегда.
- Локальный ограничитель не управляет другими облачными сервисами и не заменяет Billing. Не заявлять, что он гарантирует отсутствие списаний с карты. Сверять фактический расход между блоками.

## 8. Как используются те же ответы для гипотез

Все критерии в этом разделе нужно утвердить до main.

- H5: YandexGPT как заранее выбранная большая модель, Qwen как маленькая. Сравнить gap_A = accuracy_Yandex(A) - accuracy_Qwen(A) и gap_B аналогично; интересует gap_A - gap_B. По 8 задачам в каждом типе интервалы могут быть широкими; не делать вывод о размере модели как единственной причине различия. Дополнительных запросов Яндексу нет.
- H10: заранее выбрать A+B+F (24 задачи) и проверять правильность конечного ответа; для B это вердикт, обоснование оценивать отдельно. Среднюю confidence/100 сравнить с accuracy; ECE по пяти равным интервалам уверенности и reliability diagram. Невалидные ответы/отсутствующую confidence не скрывать: учитывать число пропусков и явно задавать знаменатели. Дополнительных запросов нет.
- H12: первичная метрика F1 класса 1, balanced accuracy вторичная. Сравнить с LogisticRegression на тех же test и train5/train20. Предложение для «не хуже»: допуск 0.05 абсолютного F1; парный bootstrap по общим тестовым строкам, 1000 повторов, seed=42. Для 5-shot нижняя односторонняя 95% граница разницы F1_LLM-F1_LR должна быть выше -0.05; для 20-shot верхняя односторонняя 95% граница должна быть ниже 0 для вывода о проигрыше. Отсутствие доказательства проигрыша не равно доказательству равенства. До запуска согласовать трактовку трёх исходов и множественных проверок. Baseline уже рассчитан, это раскрыть; прогноз относительно LLM ещё должен предшествовать их ответам.
