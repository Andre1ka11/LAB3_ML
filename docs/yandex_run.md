# Запуск YandexGPT

Рабочая ветка: `modelYandex`. Python 3.12; сам runner использует только стандартную библиотеку. Активация уже существующего окружения подходит, отдельные библиотеки для API не нужны.

## Что готово

`yandex_runner.py` выполняет 5 отладочных + 39 основных + 300 классификационных запросов. Полученные ответы сохраняются сразу. Повтор той же команды с тем же `run-id` продолжает прогон, а не оплачивает завершённые запросы заново. Основной банк и промпты не меняются.

Локальная логика проверена на имитации ответов, затем выполнены 5 реальных пилотных запросов. Ранний test_yandex.py подтверждал подключение к API, но не формат всего эксперимента.

## 1. Проверка без API

Откройте терминал в командном репозитории, где лежит `yandex_runner.py`:

```powershell
python yandex_runner.py dry-run
python -m unittest discover -s tests -p test_yandex_runner.py
```

Ожидается: 5/39/100/100/100 запросов, всего 344. При несовпадении checksum прогон останавливается. Секретные значения не выводятся.

Локальный `.env` должен содержать `YANDEX_FOLDER_ID`, `YANDEX_API_KEY`, `YANDEX_MODEL=yandexgpt-5.1`. Он исключён через `.gitignore`. Не добавляйте ключ в исходники или командную строку.

## 2. Пять пилотных запросов

```powershell
python yandex_runner.py run --stage pilot
python yandex_runner.py status
```

Пилот требует максимум 5 успешных генераций; явно отклонённый 429 может дать дополнительные попытки. Проверяем формат JSON, confidence, сохранность ответа, usage и стоимость; не отбираем модель по правильности этих пяти ответов. На весь пилот расчётный стоп-порог 10 рублей. Пока формат пилота не прошёл, основной запуск запрещён.

## 3. Прогнозы до основного прогона

```powershell
python yandex_runner.py prepare-registration
```

Команда создаёт `docs/yandex_registration.json` с точными параметрами и контрольными суммами, не делает запросов и не перезаписывает существующий файл.

Команда участников заполняет:

- `forecasts.H5`, `forecasts.H10`, `forecasts.H12`: `confirm` или `reject` (ожидаем подтверждения/опровержения гипотезы).
- `criteria`: заранее выбранные сравнения, метрики, допуски и правила статистического вывода, согласованные по `docs/yandex_plan.md`.
- `criteria_confirmed`: `true` только после согласования.

Затем этот файл нужно закоммитить до main-прогона. Runner проверяет, что локальные прогнозы совпадают с закоммиченными, и записывает идентификатор коммита в результаты. После начала основного прогона изменить регистрацию внутри того же run-id нельзя. Известные классические baseline уже были рассчитаны ранее; не представлять прогнозы как слепые относительно них.

## 4. Ночной запуск

После успешного пилота и регистрации:

```powershell
python yandex_runner.py run --stage all
```

Сохранённые pilot-запросы будут пропущены. Остальные 339 запросов выполняются последовательно. Не запускайте одновременно вторую копию; блокировка действует для данного run-id. Не создавайте разные run-id для параллельного выполнения того же банка.

Ноутбук подключить к зарядке, отключить сон при питании от сети и оставить интернет. Экран можно выключить; блокировка Windows обычно не мешает процессу. Не закрывайте терминал/VS Code и крышку, если закрытие усыпляет компьютер. Сон и отключение питания программа предотвратить не может.

После обычной остановки повторите ту же команду. При timeout/обрыве ответ мог быть тарифицирован сервером: runner остановится и запретит автоповтор. В таком случае сохраните каталог, проверьте журнал и Billing; не удаляйте историю для обхода защиты. Ошибки доступа 401/403 и повторяющиеся 429 тоже останавливают запуск.

При некорректном JSON от модели, отказе или обрезанном ответе результат сохраняется и не заменяется новой попыткой. Это часть качества модели. Пилот с таким форматом не допускает основной прогон до технического разбора и согласования общего промпта.

## 5. Результаты и бюджет

Каталог по умолчанию: `results/models/yandex/yandex-v1/`.

- `events.jsonl`: первичный журнал начала попыток, ответов и ошибок, записывается с flush/fsync.
- `<request_id>.response.txt`: исходный ответ API до разбора; содержит ответы модели, не ключ.
- `responses.jsonl`: удобная производная выгрузка завершённых ответов; восстанавливается командой `status`.
- `config.json`: неизменные параметры, hashes и бюджет данного прогона.
- `registration_commit.txt`: коммит прогнозов, привязанный к основному прогону.
- `.lock`: служебный файл блокировки. После нормального завершения файл остаётся, но блокировка освобождается ОС. Не удалять во время работы.

По умолчанию расчётный лимит всего запуска 1000 рублей, пилота 10 рублей. Перед очередным запросом резервируется консервативная оценка его стоимости; после ответа учитываются реальные usage. Тариф зафиксирован в коде: 0.8 рубля за 1000 входных и выходных токенов, без инструментов. Это локальный расчёт, а не ограничение платёжного аккаунта: проверяйте грант и Billing. Если сервер не сообщил usage, дальнейшие запросы запрещаются до проверки. Уже завершённые запросы учитываются и после перезапуска.

Программа не оценивает научные гипотезы, не исполняет код из ответов LLM и не пишет выводы отчёта. Эти этапы выполняются по сохранённым ответам отдельно. Коммит прогнозов и запуск основного прогона фиксируются отдельно; push выполняется только по отдельному запросу.

## Уточнение парсинга после пилота

Версия парсера `1.1-outer-markdown-only` принимает один JSON-объект внутри единственной внешней Markdown-оболочки (три обратные кавычки, с меткой json или без неё). Снимается только оболочка; текст до/после блока не допускается. Ответ, обоснование и confidence не исправляются. Синтаксические ошибки сгенерированного кода сохраняются.

`events.jsonl` и response.txt остаются неизменными. Производный responses.jsonl пересобирается из них с полями original_error, parser_version, strict_format_ok и актуальным parsed. markdown_wrapper означает нарушение требования чистого JSON; оно учитывается отдельно от правильности содержательного ответа. Неразбираемые ответы остаются неуспехами, в знаменателе их не исключаем. Это правило должно применяться ко всем моделям одинаково.

Реальный пилот завершён: 5 ответов, 1635 токенов, расчётная стоимость 1.308 рубля. Все пять ответов содержат внешнюю Markdown-оболочку; повторные генерации для их разбора не требуются. В P04 обнаружена синтаксическая ошибка кода, она не исправлялась.
