# Результаты части YandexGPT

## Основной файл

Откройте `notebooks/yandex_analysis.ipynb`. Ноутбук выполнен, таблицы и графики сохранены внутри. При Run All анализ пересчитывается локально из журнала ответов; запросов к API нет. Код из ответов модели повторно не запускается.

Для нового окружения: Python 3.12 и `pip install -r requirements-analysis.txt`. В VS Code выберите это окружение как kernel.

## Что уже готово

- Все 344 уникальных ответа: 5 pilot + 39 main + 300 E. Две сетевые попытки с неизвестным результатом сохранены отдельно, разрешения пользователя на повторы тоже в журнале.
- Автоматические оценки 24 задач A/B/F с 95% bootstrap CI. B здесь оценивается по вердикту; объяснения проверяются отдельно.
- Классификация 0/5/20-shot, F1 редкого класса, balanced accuracy, coverage, отказы, сравнение с LogisticRegression/GaussianNB и константой на одинаковых строках.
- H10: зарегистрированная проверка уверенности, ECE и диаграмма надёжности.
- H12: парный bootstrap и заранее выбранный допуск 0.05 F1. Все границы и алгоритмический статус в hypotheses.json.
- Все 8 программ D извлечены без исправлений и выполнены после просмотра исходников, в отдельных процессах с очищенным окружением и без чтения .env; сохраняются stdout/stderr, код возврата и hash исходного кода. Это техническая проверка, не замена двух независимых оценок методологии.
- Семь графиков и пять исходных примеров неверных ответов с эталонами. Поле анализа причин оставлено участникам.

## Что сделать двум участникам

1. Получить материалы `analysis/yandex/review/REVIEW.md` или `responses.json`.
2. Независимо заполнить каждый свой `reviewer_1.csv` / `reviewer_2.csv`: для B/C балл 0-2; для D флаги ошибок 0/1 либо N/A по применимости.
3. Не смотреть `analysis/yandex/review_key.json`: это ключ соответствия для организатора.
4. Для соблюдения слепой проверки перемешать этот пакет с ответами остальных моделей и переобозначить IDs. Пакет только Яндекса сам по себе не скрывает источник ответов.
5. Сохранить обе исходные оценки, рассчитать согласие, при kappa<0.6 уточнить рубрику и переоценить; разногласия разрешить обсуждением. Не заменять пустые поля нулями.

После заполнения CSV пересчитать:

```powershell
python scripts/analyze_yandex.py
```

Формы с человеческими оценками при повторном анализе не перезаписываются. В `review_status.json` будут заполненные пары, kappa и статус. При константных одинаковых оценках kappa может быть неопределённой: смотреть долю согласия и явно отмечать ограничение.

## Что ждёт остальных моделей

H5 требует совпадающих A/B ответов Qwen3 4B. Общая сравнительная таблица, полный model x type heatmap и exact McNemar между LLM требуют результатов других участников. Яндекс уже имеет свою строку и готовые автоматические метрики; отсутствующие значения оставлены пустыми.

Итоговые выводы отчёта, пять объяснений причин ошибок, ограничения и практические рекомендации заполняются командой по фактическим данным. Общее качество по всем 39 задачам до завершения ручной проверки не заявляется.

## Воспроизведение

```powershell
python -m unittest discover -s tests -p 'test_yandex_*.py'
python scripts/analyze_yandex.py
python scripts/build_yandex_notebook.py
python scripts/execute_yandex_notebook.py
```

Анализ не делает генераций. Флаг `--execute-reviewed-code` является отдельным явным действием для повторного запуска сохранённых программ D; не нужен для обычного пересчёта ноутбука. Не исправляйте код перед оценкой pass@1.
